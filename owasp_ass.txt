### Identify Protected Resources

List at least five pages, functions, records, or resources that require access restrictions.

* No. | Protected Resource / Function | Why Access Should Be Restricted
* 1 | **Hardware Diagnostics (`/dashboard/hardware`)** | Shows sensitive microcontroller details, sensor pins, and device IPs. Only SuperAdmins should see this so normal users cannot mess with the physical hardware setup.
* 2 | **Clear All History (`DELETE /dashboard/history/clear`)** | Wipes out all waste logs and resets all bin data. Only SuperAdmins should be allowed so that important records and proof of waste disposal are not accidentally or maliciously deleted.
* 3 | **Seed Demo Data (`POST /api/system/seed-mock-data`)** | Erases real data and replaces it with fake 30-day testing data. Restricted to SuperAdmins so live data is not overwritten during actual operations.
* 4 | **Empty Bin Action (`POST /api/bins/{slug}/empty`)** | Resets a bin's fill level to 0% and logs who emptied it. Restricted to logged-in Admins so random people on the internet cannot fake bin evacuations.
* 5 | **Export Reports (PDF / CSV) (`/dashboard/export`, `/dashboard/export/csv`)** | Downloads detailed history logs and operator emails. Restricted to logged-in staff to protect internal data and privacy.
* 6 | **User Profile & 2FA (`/profile`, `/2fa/*`)** | Contains account passwords, email changes, and 2FA security codes. Restricted so users can only view and edit their own account, not anyone else's.

* Test performed:

  The system should block the request and show an **HTTP 403 Forbidden** error ("Unauthorized access. Only SuperAdmin accounts can perform this operation.").

* Actual result:
  The system successfully blocked the Admin and returned an **HTTP 403 Forbidden** error. The `role:superadmin` middleware stopped the request.

* Was unauthorized access possible? (Yes/No)
  **No**

  If regular users could access SuperAdmin features, they could wipe out all waste history records or view sensitive hardware settings.

  1. Keep using server-side role checks (`role:superadmin`) on all sensitive routes so direct URL typing is always blocked.
  2. Use Laravel Policy rules on models for an extra layer of protection.
